Viacheslav Munister is an author, researcher, and digital heritage specialist, as well as a product architect and software developer. He is a member of the heritage associations En Quête de Patrimoine and Histoire d’en Parler. His work focuses on architecture, urban culture, collective memory, and the preservation and reinterpretation of cultural heritage through digital technologies.

Munister / Practice

Applied systems practice

Selected live systems, each organised around a concrete research or operational problem, a data model and a maintainable delivery path.

Virtual museum · curation and engineering

EPRIS Museum

Public-domain and openly licensed work — sculpture and painting from the Art Institute of Chicago, the Cleveland Museum of Art and the National Gallery of Art, prize-winning nature photography and James Webb Space Telescope exposures from Wikimedia Commons — hung as one route across 39 halls and more than 500 works, from Archaic Greek bronze to images taken this year. Every object is drawn to its own recorded scale: paintings on a shared centreline, sculpture standing on the floor at its true height, worked out from its own photograph where no measurement survives. Each work keeps its author, date, licence and museum of origin, and each hall is a stable address you can cite. A digital museum with no building of its own, curated from Milan, Italy.

Retail operations core · method, model, invariants

Horreum

An operations core for a clothing retailer, built in full without naming the client. Under the retail vocabulary sit three problems with names of their own: schema matching, deterministic record linkage, and a materialised aggregate kept correct under three concurrent writers. Supplier snapshots are matched and imported deterministically, every invariant is enforced by the mechanism that holds it, and an undo is a forward operation with a precondition rather than a delete.

Learning systems · product and technology

TeachEd

A language-teaching workspace that converts planning materials, video and vocabulary into structured classroom objects. A lesson is an editable sequence of tasks, constraints and outputs rather than a static worksheet: boards, generated worksheets, YouTube turned into class material and more than thirty classroom games share one data model, so material composed once can be revised, shared and re-run online or on paper. I lead the product model, architecture and release process.

Editorial research infrastructure

EPRIS Journal

An independent journal used as a testbed for durable cultural publishing. Its infrastructure models articles, objects, translations and media as linked editorial records, then carries them through validation, review, publication and deployment. The resulting digital passport is not a decorative archive: it establishes provenance, re-use paths and a workable research layer around each publication.

eprisjournal.com
Oracle data modelling · open source

Schemata

A browser-native relational modeller for Oracle Database, built as plain HTML5 and ES modules with no build step and no backend. It works like a design tool: a filterable table list, a minimap, a ⌘K command palette, colour-coded tables and relation highlighting around the selection. A relationship is created the way Oracle Data Modeler does it, by carrying the parent key into the child table, and the model round-trips through Oracle DDL: a hand-written tokenizer imports tables, constraints, indexes and comments, and the generator writes an equivalent schema back out. An in-browser SQL sandbox runs the model against SQLite, so a schema can be queried before it ever reaches a real database. Models are saved as JSON, so a schema can be versioned and reviewed in Git. Interface in Ukrainian and English.

munister.com.ua/modeler
Public archive · collection and interface

Museum of Donetsk Photography

A photographic museum of a city that can now only be walked through in pictures. Over four hundred images are gathered, de-duplicated and passported through a three-stage pipeline, then hung across eight halls, including one built from freely licensed work by other photographers. Readers can submit their own frames: intake, size limits and re-encoding are handled by a separate service, so the archive grows without opening the site to unchecked uploads.

Digital humanities · research, text, interface

Italy Chapter

A bilingual digital-humanities study of Italy’s visual language in proportion, light and material. The interface works as an argument: an atlas, a timeline and controlled side-by-side comparisons make the evidence inspectable rather than leaving it as atmosphere. Research, editorial structure, visual system and implementation are developed as one method.

Munister / Competencies

Applied systems and prototypes

Depth across the layers a working system actually needs: language and framework choice, the data model underneath, the infrastructure that keeps it running, and the standards that let it talk to the outside world.

Languages

Languages

TypeScript and JavaScript for most production work, Python for services and automation, SQL across PostgreSQL, SQLite and Oracle, Swift for native iOS, and C++ where a system needs to sit closer to the machine.

Frontend

Frameworks and interfaces

React and Next.js for application-shaped interfaces, Vite for build tooling, SwiftUI for native iOS, Tailwind for design systems that need to move fast without losing consistency. Not every system gets a framework: several are deliberately plain HTML, CSS and JavaScript with no build step, chosen because the problem didn't need one.

Data & backend

Data and backend

PostgreSQL schema design, including trigram search indexes and invariants held correct under concurrent writers; SQLite for lighter deployments; Oracle relational modelling. Flask and Python for isolated backend services, REST APIs designed with their own rate limits, and deterministic import and reconciliation pipelines for messy source data.

Infrastructure & operations

Infrastructure and operations

Linux server administration end to end: nginx configuration and TLS, PM2 and systemd for process supervision, Docker for isolated services, CI/CD pipelines through GitHub Actions. Backup and disaster-recovery design treated as part of the data model, not an afterthought.

Integration & standards

Integration and standards

AI and LLM APIs wired into editorial and cataloguing workflows, IANA time-zone data and the Intl API for computation that survives daylight-saving changes, TopoJSON for geography that has to stay small, IIIF and open-access museum APIs for cultural collections, JWT authentication, and WebSocket-based real-time audio and messaging.
