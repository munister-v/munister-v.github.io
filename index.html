Virtual museum · curation and engineering

EPRIS Museum

Public-domain and openly licensed work — sculpture and painting from the Art Institute of Chicago, the Cleveland Museum of Art and the National Gallery of Art, prize-winning nature photography and James Webb Space Telescope exposures from Wikimedia Commons — hung as one route across 39 halls and more than 500 works, from Archaic Greek bronze to images taken this year. Every object is drawn to its own recorded scale: paintings on a shared centreline, sculpture standing on the floor at its true height, worked out from its own photograph where no measurement survives. Each work keeps its author, date, licence and museum of origin, and each hall is a stable address you can cite.

Retail operations core · method, model, invariants

Horreum

An operations core for a clothing retailer, written up in full without naming the client. Under the retail vocabulary sit three problems with names of their own: schema matching, deterministic record linkage, and a materialised aggregate kept correct under three concurrent writers. The write-up states the import as an algorithm with the cost of every step, lists the invariants beside the mechanism that holds each one, and then goes down to the statements themselves: what a supplier snapshot says about the articles it does not mention, and why an undo has to be a forward operation with a precondition. The model itself is a page of its own: six tables you can open, each naming who is allowed to write it.

Learning systems · product and technology

TeachEd

A language-teaching workspace that converts planning materials, video and vocabulary into structured classroom objects. A lesson is an editable sequence of tasks, constraints and outputs rather than a static worksheet: boards, generated worksheets, YouTube turned into class material and more than thirty classroom games share one data model, so material composed once can be revised, shared and re-run online or on paper. I lead the product model, architecture and release process.

Editorial research infrastructure

EPRIS Journal

An independent journal used as a testbed for durable cultural publishing. Its infrastructure models articles, objects, translations and media as linked editorial records, then carries them through validation, review, publication and deployment. The resulting digital passport is not a decorative archive: it establishes provenance, re-use paths and a workable research layer around each publication.

Oracle data modelling · open source

Schemata

A browser-native relational modeller for Oracle Database, built as plain HTML5 and ES modules with no build step and no backend. It works like a design tool: a filterable table list, a minimap, a ⌘K command palette, colour-coded tables and relation highlighting around the selection. A relationship is created the way Oracle Data Modeler does it, by carrying the parent key into the child table, and the model round-trips through Oracle DDL: a hand-written tokenizer imports tables, constraints, indexes and comments, and the generator writes an equivalent schema back out. An in-browser SQL sandbox runs the model against SQLite, so a schema can be queried before it ever reaches a real database. Models are saved as JSON, so a schema can be versioned and reviewed in Git. Interface in Ukrainian and English.

Public archive · collection and interface

Museum of Donetsk Photography

A photographic museum of a city that can now only be walked through in pictures. Over four hundred images are gathered, de-duplicated and passported through a three-stage pipeline, then hung across eight halls, including one built from freely licensed work by other photographers. Readers can submit their own frames: intake, size limits and re-encoding are handled by a separate service, so the archive grows without opening the site to unchecked uploads.

Italy Chapter

A bilingual digital-humanities study of Italy’s visual language in proportion, light and material. Munister / Systems register

Applied systems and prototypes

Five further implementations. Each addresses a specific operational constraint through data modelling, computational logic or infrastructure design.

Mania Group Retail operations · data model A headless retail system built around the operational problem WordPress could not resolve: variants, supplier prices and orders need a stable model rather than a collection of product pages. The Next.js and TypeScript layer reads live WooCommerce data without duplicating the legacy admin, represents stock as a size-level matrix, normalises supplier spreadsheets into a price-import pipeline and keeps the order flow traceable from catalogue state to fulfilment. EPRIS Showcase Editorial ingestion · media reliability A controlled intake pipeline for public cultural submissions. Records pass through an editorial decision state before publication; the API is isolated from the journal release cycle and protected by its own rate limit. Media is normalised once with Sharp and retained locally, removing a common archival failure mode: a published record must not disappear because a contributor’s external image host changes or fails. Munister Agency Temporal-geographic computation A deliberately lightweight multilingual web system whose central method is computational rather than presentational. The coverage map calculates working-hour overlap by state from IANA time-zone rules via Intl, so daylight-saving changes are resolved from source data rather than maintained by hand. Census geometry is reduced to a 32 KB TopoJSON model, making an evidence-based geographic interface fast enough for an ordinary static deployment. AM Publishing Publishing operations · distributed services A publication platform designed to keep editorial metadata independent from sales channels. Each title holds a maintained offer set instead of one hard-coded retailer, so regional availability can change without rewriting the publication. The frontend stays static and auditable; transactional checkout and the radio service are separated into purpose-built services, reducing coupling between catalogue, payment and streaming operations. ARM OS Human-computer interaction prototype A browser-based operating-environment prototype used to study how familiar desktop mechanics translate into a financial interface. A single-file window manager implements coordinate state, z-order, resize, snap and search behaviour, then connects seventeen tools through shared interaction rules. The experiment combines embedded live services with native utilities, including rate conversion, loan calculation, charting and persistent local documents.
Munister / Systems

How these are built

Ten of the systems above, written up properly, and one that cannot be named: the data model, the pipeline drawn step by step, and the failure that changed the design.

Each write-up answers the same three questions. What is this actually for? What shape is the data underneath it? And what went wrong badly enough to be worth telling someone about? The diagrams carry the argument, every step and branch and dead end drawn as it runs, and the prose explains why the arrows go that way.
