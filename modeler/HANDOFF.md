Анімацію появи таблиці тому свідомо не робили.
- **SQL-пісочниця:** нова кнопка «Пісочниця» (import/migrate/export group, і в мобільному «Інші дії»). `sqlite-gen.js` — окремий, спрощений генератор DDL під SQLite (не той самий, що `ddl-gen.js` для реального Oracle): NUMBER-сімʼя → NUMERIC, решта → TEXT/BLOB, FK тільки inline (SQLite не вміє `ALTER TABLE ADD CONSTRAINT`), `SYSDATE`/`SYSTIMESTAMP` → `CURRENT_TIMESTAMP`, `.NEXTVAL` і будь-який нерозпізнаний Oracle-вираз у DEFAULT — просто відкидаються (безпечніше, ніж лишити як є: SQLite мовчки зберігає незнайомий bareword як текстовий літерал замість помилки — на цьому спіймались одразу, `SYSTIMESTAMP` без спецкейса літерально писався в колонку). Кожен CREATE TABLE/INDEX/VIEW виконується окремо з try/catch — що не вийшло, потрапляє в список попереджень, решта схеми все одно піднімається. `bump-version.sh` перевіряє синтаксис і цих двох файлів так само, як і решту.

## Недавно сделано (2026-09-22)
- **Скорость перетаскивания на больших схемах:** `renderRelations()` — это `gRels.innerHTML = ...` по ВСЕМ FK модели, и она дёргалась на каждый `pointermove` во время драга (через `store.silent(fn, 'move')` → подписка в конструкторе `Diagram`). На синтетической модели 300 таблиц / 413 FK — 13мс медиана на кадр (уже хуже 60fps). Профилировано и исправлено: `store.silent`/`emit` теперь принимают третий аргумент `detail` — id'шники, которые реально сдвинулись (`js/model.js`). `Diagram` подписывается `(r, ids) =>`: если `ids` пришёл — точечный `updateDragPositions(ids)` (патчит `transform` только у сдвинутых `<g>` и `outerHTML` только у `.rel[data-id]`, которые их касаются — остальные сотни элементов не трогает); `ids === undefined` — старый полный `renderRelations()` (безопасный фолбэк для любого будущего вызова, который забудет передать detail); `ids === []` — ничего не делать (drag зоны: у зон нет ни таблиц, ни связей, а свой transform зона уже патчит сама). Задеты все 6 мест, где раньше звался `store.silent(..., 'move')`: `diagram.js` (drag таблицы/мульти-драг/зона/ресайз зоны) и `app.js` (нажатие стрелок, одиночное и мульти). Результат на той же модели: 0.6мс медиана — **~22×**. Проверено на точное совпадение с полным рендером (`relMarkup`/`depMarkup` — общие хелперы для обоих путей, так что расхождений в разметке быть не может).
- **Важно если трогаешь `store.silent()`:** третий аргумент теперь ОБЯЗАТЕЛЕН для любого нового вызова с `reason:'move'`, который двигает таблицы/view — иначе `Diagram` тихо откатится на медленный полный рендер (корректно, но без ускорения). Список id передавай тот, что реально сдвинулся, не всё выделение.

## Что дальше (план)
1. **Большие схемы:** несколько диаграмм (предметные области), цветные зоны, выделение рамкой, LoD-культинг при большом числе таблиц/низком зуме, орфографическая маршрутизация связей — всё уже сделано (`diagrams-ui.js`, `resolveOverlaps`/LoD в `diagram.js`, `canvas-search.js`). Точечное обновление при драге (см. выше) снимает основной перф-затык на 300+ таблицах; не профилировали именно полный `render()` (открытие модели, autoLayout, LoD-переключение по зуму) — если станет узким местом, тот же подход (patch, не rebuild) применим и там.
2. **Качество:** готово на практическом уровне (именование PK с автофиксом, циклы FK, повторяющиеся группы). Полная проверка 2NF/3NF не сделана — модель не хранит функциональные зависимости, это отдельная (большая) задача.
3. **Логическая модель:** сущности, домены, подтипы, преобразование в физическую, нотации Barker и IE.
4. **Open source:** отдельный репозиторий, тесты парсера и diff, GitHub Actions, README со скриншотами.
5. **С бэкендом на VPS:** Git/YAML-модели, Liquibase/Flyway, подключение к живой Oracle, совместная работа. Лёгкая часть запроса «нет эмуляции» закрыта локальной SQL-пісочницею (SQLite/WASM, без бекенда) — реальный Oracle остаётся отдельной, куда большей задачей именно этого пункта.
